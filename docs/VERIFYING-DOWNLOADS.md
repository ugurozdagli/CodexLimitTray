# Verify a download before running it

Use the official repository: **https://github.com/ugurozdagli/CodexLimitTray**. No maintainer account, API key, or Codex session is part of its release files.

## 1. Check the SHA-256 digest

Download the EXE or ZIP and `SHA256SUMS.txt` from the **same release**. In PowerShell:

```powershell
Get-FileHash .\CodexLimitTray-v1.2.0-win-x64.exe -Algorithm SHA256
```

Compare the complete hash to the corresponding filename in `SHA256SUMS.txt`. A match checks integrity against that manifest. A maliciously replaced file and manifest could still match, so this is not proof of publisher identity or safety on its own.

## 2. Check GitHub build provenance

The public release workflow creates a build attestation for its downloadable EXE and ZIP. With the official GitHub CLI installed:

```powershell
gh attestation verify .\CodexLimitTray-v1.2.0-win-x64.exe --repo ugurozdagli/CodexLimitTray
```

The ZIP can be verified with the same command and its filename. Inspect the result's repository, commit, and workflow. The attestation is generated by GitHub Actions; local development builds do not have one.

Source: [GitHub's artifact-attestation guide](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations).

## 3. Review the source and build logs

The release points to a public source commit. The **Actions** tab shows the build and offline checks. You can build the app yourself with the .NET 10 SDK.

## What this does not promise

CLT's initial release has no Windows code-signing certificate. An attestation is not an Authenticode publisher signature and does not suppress SmartScreen or guarantee a clean antivirus result. Do not disable security protections. If you cannot establish trust in a download, do not run it.
